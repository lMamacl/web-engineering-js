Tak, rozumiesz ogólny kierunek bardzo dobrze. Są jednak dwie ważne korekty:

1. `ng generate component students` wygeneruje **nowy komponent**, a nie moduł.
2. W tym zadaniu najprawdopodobniej chodzi o zmianę selektora istniejącego głównego komponentu na `<students>`, a niekoniecznie o tworzenie osobnego komponentu `Students`.

## 1. Czy tworzyć `students`?

Masz już główny komponent aplikacji, np. `App`. W jego dekoratorze znajduje się:

```typescript
@Component({
  selector: 'app-root',
  ...
})
```

Zmieniasz:

```typescript
selector: 'app-root'
```

na:

```typescript
selector: 'students'
```

Następnie w `src/index.html` zmieniasz:

```html
<app-root></app-root>
```

na:

```html
<students></students>
```

W ten sposób istniejący główny komponent aplikacji będzie miał wymagany selektor `<students>`.

Polecenie:

```powershell
ng generate component students
```

ma sens tylko wtedy, gdy prowadzący rzeczywiście wymaga osobnego komponentu o nazwie `Students`. W opisie jest napisane „w wygenerowanym komponencie zmień jego selektor na `<students>`”, więc bezpieczniej wykorzystać główny komponent wygenerowany razem z aplikacją.

# 2. Klasa `Student`

Tworzysz osobny plik, np.:

```text
src/app/student.ts
```

W nim będzie model danych jednego studenta:

```typescript
export class Student {
  private _imie: string;
  private _nazwisko: string;
  private _wiek: number;
  private _oceny: number[];

  constructor(
    imie: string,
    nazwisko: string,
    wiek: number,
    oceny: number[] = []
  ) {
    this._imie = imie;
    this._nazwisko = nazwisko;
    this._wiek = wiek;
    this._oceny = oceny;
  }

  get imie(): string {
    return this._imie;
  }

  set imie(value: string) {
    this._imie = value;
  }

  get nazwisko(): string {
    return this._nazwisko;
  }

  set nazwisko(value: string) {
    this._nazwisko = value;
  }

  get wiek(): number {
    return this._wiek;
  }

  set wiek(value: number) {
    this._wiek = value;
  }

  get oceny(): number[] {
    return this._oceny;
  }

  set oceny(value: number[]) {
    this._oceny = value;
  }
}
```

## Co daje getter i setter?

Zamiast odwoływać się bezpośrednio do prywatnego pola:

```typescript
student._wiek
```

korzystasz z właściwości:

```typescript
student.wiek
```

Odczyt:

```typescript
console.log(student.wiek);
```

wywołuje getter:

```typescript
get wiek(): number {
  return this._wiek;
}
```

Przypisanie:

```typescript
student.wiek = 25;
```

wywołuje setter:

```typescript
set wiek(value: number) {
  this._wiek = value;
}
```

W setterze można później dodać walidację, np. zakazać wieku mniejszego od zera.

# 4. Ukrywanie i pokazywanie informacji

To jest najważniejszy element, którego nie rozumiesz jeszcze do końca.

Angular nie ukrywa elementu samoczynnie. Ty przechowujesz w komponencie informację, czy szczegóły mają być widoczne.

Przykładowo:

```typescript
pokazSzczegoly = false;
```

W szablonie:

```html
<button (click)="pokazSzczegoly = !pokazSzczegoly">
  Pokaż szczegóły
</button>

@if (pokazSzczegoly) {
  <p>Wiek: {{ student.wiek }}</p>
  <p>Oceny: {{ student.oceny }}</p>
}
```

## Co oznacza `!`?

Jeżeli:

```typescript
pokazSzczegoly = false;
```

to:

```typescript
!pokazSzczegoly
```

oznacza `true`.

Jeżeli klikniesz ponownie:

```typescript
!true
```

daje `false`.

Czyli każde kliknięcie przełącza stan:

```text
false → true → false → true
```

A `@if` decyduje, czy zawartość ma zostać wyrenderowana:

```html
@if (pokazSzczegoly) {
  ...
}
```

Gdy wartość jest `false`, Angular w ogóle nie umieszcza tego fragmentu w stronie.

---

## Osobny stan dla każdego studenta

Jeżeli masz pięciu studentów, pojedyncza zmienna:

```typescript
pokazSzczegoly = false;
```

może być niewystarczająca, bo wszyscy studenci używaliby jednego stanu.

Lepsze rozwiązanie to przechowywanie aktualnie rozwiniętego studenta:

```typescript
rozwinietyStudent: Student | null = null;
```

Metoda:

```typescript
pokazSzczegoly(student: Student): void {
  if (this.rozwinietyStudent === student) {
    this.rozwinietyStudent = null;
  } else {
    this.rozwinietyStudent = student;
  }
}
```

Działa to tak:

- na początku `rozwinietyStudent` jest `null`, więc nikt nie jest rozwinięty,
- kliknięcie studenta zapisuje go do zmiennej,
- kliknięcie tego samego studenta ustawia `null`,
- kliknięcie innego studenta zastępuje poprzednią wartość.

W HTML-u:

```html
@for (student of studenci; track $index) {
  <div class="student">
    <h2 (click)="pokazSzczegoly(student)">
      {{ student.imie }} {{ student.nazwisko }}
    </h2>

    @if (rozwinietyStudent === student) {
      <p>Wiek: {{ student.wiek }}</p>

      @for (ocena of student.oceny; track $index) {
        <span>{{ ocena }}</span>
      }
    }
  </div>
}
```

Najważniejsza część to:

```html
@if (rozwinietyStudent === student)
```

Angular sprawdza, czy aktualnie wybrany student jest tym studentem, którego właśnie wyświetla.

# 5. Czerwony kolor dla oceny `2.0`

W HTML-u:

```html
<span [class.ocena-negatywna]="ocena === 2.0">
  {{ ocena }}
</span>
```

Angular doda klasę CSS tylko wtedy, gdy warunek jest prawdziwy.

W CSS:

```css
.ocena-negatywna {
  color: red;
  font-weight: bold;
}
```

Dla oceny `4.0` HTML będzie zachowywał się tak, jakby klasy nie było.

Dla oceny `2.0` otrzymasz efekt podobny do:

```html
<span class="ocena-negatywna">2</span>
```

To jest przykład **wiązania klasy CSS**.

# 6. Komponent `AddStudent`

Ten komponent będzie formularzem dodawania nowej osoby.

Generujesz go:

```powershell
ng generate component add-student --project zadanie-4
```

Powinien przechowywać tymczasowe wartości formularza:

```typescript
imie = '';
nazwisko = '';
wiek = 18;
```

W formularzu:

```html
<input [(ngModel)]="imie" placeholder="Imię">
<input [(ngModel)]="nazwisko" placeholder="Nazwisko">
<input [(ngModel)]="wiek" type="number" placeholder="Wiek">

<button (click)="dodaj()">
  Zapisz studenta
</button>
```

`[(ngModel)]` jest połączeniem dwóch mechanizmów:

- `[value]` — dane z klasy trafiają do pola,
- `(input)` — dane z pola trafiają do klasy.

Dlatego wpisanie `Jan` do inputa automatycznie ustawi:

```typescript
this.imie = 'Jan';
```

Do używania `ngModel` trzeba dodać `FormsModule` do `imports` komponentu.

# 7. Czym jest `EventEmitter`?

`AddStudent` jest dzieckiem głównego komponentu.

Ma ono dane formularza, ale główna lista studentów znajduje się w rodzicu. Dziecko nie powinno bezpośrednio modyfikować tablicy rodzica.

Schemat komunikacji:

```text
AddStudent                         App
formularz                          lista studentów
    |                                      |
    | ---- wysyła nowego studenta ------> |
```

Do wysłania informacji do rodzica używasz `EventEmitter`.

W komponencie `AddStudent`:

```typescript
@Output() studentAdded = new EventEmitter<Student>();
```

Po kliknięciu przycisku tworzysz obiekt i emitujesz go:

```typescript
dodaj(): void {
  const student = new Student(
    this.imie,
    this.nazwisko,
    this.wiek,
    []
  );

  this.studentAdded.emit(student);
}
```

`emit(student)` oznacza:

> „Rodzicu, formularz został zakończony i oto nowy student”.

W komponencie rodzica używasz komponentu:

```html
<app-add-student
  (studentAdded)="dodajStudenta($event)"
></app-add-student>
```

Tutaj:

```html
(studentAdded)="dodajStudenta($event)"
```

oznacza:

- nasłuchuj eventu `studentAdded`,
- kiedy się pojawi, wywołaj metodę `dodajStudenta`,
- `$event` to obiekt przekazany przez `emit`.

W rodzicu:

```typescript
dodajStudenta(student: Student): void {
  this.studenci.push(student);
}
```

Czyli cały przepływ wygląda tak:

```text
1. Użytkownik wpisuje dane.
2. ngModel zapisuje je w AddStudent.
3. Użytkownik klika „Zapisz”.
4. AddStudent tworzy obiekt Student.
5. AddStudent wykonuje studentAdded.emit(student).
6. App odbiera obiekt przez $event.
7. App wykonuje studenci.push(student).
8. Angular odświeża listę.
```

# 8. Pokazywanie formularza dodawania

W rodzicu możesz mieć:

```typescript
pokazFormularzDodawania = false;
```

Przycisk:

```html
<button (click)="pokazFormularzDodawania = true">
  Dodaj studenta
</button>
```

Formularz:

```html
@if (pokazFormularzDodawania) {
  <app-add-student
    (studentAdded)="dodajStudenta($event)"
  ></app-add-student>
}
```

Po zapisaniu możesz ukryć formularz:

```typescript
dodajStudenta(student: Student): void {
  this.studenci.push(student);
  this.pokazFormularzDodawania = false;
}
```

Ponownie używasz tutaj tej samej idei co przy szczegółach:

```text
false → formularz ukryty
true  → formularz widoczny
```

# 9. Komponent `EditStudent`

Wymaganie mówi:

> Wygeneruj komponent `EditStudent`. Zadbaj o to, aby pola w szablonie były wypełnione aktualnymi wartościami obiektu.

To sugeruje, że powinien istnieć osobny komponent z formularzem edycji.

Możesz go wygenerować:

```powershell
ng generate component edit-student --project zadanie-4
```

Ten komponent powinien otrzymać wybranego studenta od rodzica.

Do przekazania danych z rodzica do dziecka służy `@Input()`.

W `EditStudent`:

```typescript
@Input({ required: true }) student!: Student;
```

W rodzicu:

```html
<app-edit-student
  [student]="wybranyStudent"
></app-edit-student>
```

Tutaj:

```html
[student]="wybranyStudent"
```

oznacza:

> „Przekaż wartość `wybranyStudent` do właściwości `student` w komponencie dziecka”.

Wybór studenta może wyglądać tak:

```typescript
wybranyStudent: Student | null = null;

wybierzDoEdycji(student: Student): void {
  this.wybranyStudent = student;
}
```

W tabeli lub przy każdym studencie:

```html
<button (click)="wybierzDoEdycji(student)">
  Edytuj
</button>
```

A formularz pokazujesz warunkowo:

```html
@if (wybranyStudent) {
  <app-edit-student
    [student]="wybranyStudent"
  ></app-edit-student>
}
```

# 10. Czy edycja może być w tabeli?

Technicznie tak. Możesz zamienić komórki tabeli na pola `input` po kliknięciu.

Przykładowo:

```html
<td>
  @if (student === wybranyStudent) {
    <input [(ngModel)]="student.imie">
  } @else {
    {{ student.imie }}
  }
</td>
```

Jednak w tym zadaniu wymaganie mówi konkretnie o wygenerowaniu komponentu `EditStudent`. Dlatego sama edycja bezpośrednio w tabeli może nie wystarczyć do zaliczenia.

Najbezpieczniej:

- lista studentów może być tabelą,
- przy każdym wierszu umieszczasz przycisk `Edytuj`,
- po kliknięciu pokazujesz osobny komponent `EditStudent`,
- komponent `EditStudent` może znajdować się pod tabelą albo obok niej.

Czyli:

```text
Tabela studentów
    |
    └── przycisk „Edytuj”
              |
              └── EditStudent wyświetlony pod tabelą
```

Nie musi to być specjalne okno modalne. Wystarczy zwykły formularz w osobnym komponencie.

# 11. Wypełnienie formularza aktualnymi danymi

Najprostsza wersja:

```html
<input [(ngModel)]="student.imie">
<input [(ngModel)]="student.nazwisko">
<input [(ngModel)]="student.wiek">
```

Jeżeli do `EditStudent` przekazano studenta:

```typescript
student = {
  imie: 'Jan',
  nazwisko: 'Kowalski',
  wiek: 21
};
```

to pola automatycznie będą zawierały:

```text
Jan
Kowalski
21
```

Dzieje się tak, ponieważ `ngModel` pobiera początkowe wartości z właściwości obiektu.

W bardziej rozbudowanej wersji można utworzyć kopię:

```typescript
imie = '';
nazwisko = '';
wiek = 0;
```

i załadować do niej dane wybranego studenta. Wtedy zmiany nie modyfikują od razu głównej listy. Dopiero przy przycisku `Zapisz` wysyłasz zmienione dane do rodzica.

Na zajęcia najprostsze bezpośrednie powiązanie prawdopodobnie wystarczy, ale kopia jest bardziej poprawna projektowo.

# 12. Dodawanie oceny w `EditStudent`

W komponencie edycji dodajesz:

```typescript
nowaOcena: number | null = null;
```

W HTML-u:

```html
<input
  type="number"
  [(ngModel)]="nowaOcena"
  min="2"
  max="5"
  step="0.5"
>

<button (click)="dodajOcene()">
  Dodaj ocenę
</button>
```

Metoda:

```typescript
dodajOcene(): void {
  if (this.nowaOcena === null) {
    return;
  }

  this.student.oceny.push(this.nowaOcena);
  this.nowaOcena = null;
}
```

Przepływ:

```text
1. Użytkownik wpisuje ocenę.
2. ngModel zapisuje ją do nowaOcena.
3. Użytkownik klika „Dodaj ocenę”.
4. Metoda dodajOcene() wykonuje student.oceny.push(...).
5. Ocena trafia do tablicy ocen.
6. Lista zostaje odświeżona.
```

Możesz dodatkowo sprawdzać zakres:

```typescript
if (this.nowaOcena < 2 || this.nowaOcena > 5) {
  return;
}
```

Wtedy oceny spoza zakresu nie zostaną dodane.

# 13. Najważniejsze pojęcia w jednym miejscu

## `@Input()`

Dane idą z rodzica do dziecka:

```text
App ───────> EditStudent
```

Przykład:

```html
<app-edit-student [student]="wybranyStudent" />
```

## `@Output()`

Informacja idzie z dziecka do rodzica:

```text
AddStudent ───────> App
```

Przykład:

```typescript
@Output() studentAdded = new EventEmitter<Student>();
```

oraz:

```typescript
this.studentAdded.emit(student);
```

## `@if`

Warunkowo pokazuje fragment HTML:

```html
@if (pokazFormularz) {
  <app-add-student />
}
```

## `(click)`

Reaguje na kliknięcie:

```html
<button (click)="otworzFormularz()">
```

## `[(ngModel)]`

Łączy wartość inputa z polem klasy:

```html
<input [(ngModel)]="imie">
```

## `[class.nazwa-klasy]`

Warunkowo dodaje klasę CSS:

```html
<span [class.ocena-negatywna]="ocena === 2.0">
```

---

Najprostszy model całej aplikacji wygląda więc tak:

```text
App
│
├── przechowuje tablicę Student[]
├── wyświetla listę
├── pokazuje/ukrywa szczegóły
├── otwiera AddStudent
│     └── wysyła nowego studenta przez @Output()
│
└── otwiera EditStudent
      ├── przekazuje studenta przez @Input()
      └── pozwala zmienić dane i dodać ocenę
```

Najważniejsze jest rozróżnienie:

- **dane główne** powinny znajdować się w komponencie rodzica `App`,
- `AddStudent` i `EditStudent` są formularzami,
- formularze komunikują się z rodzicem przez `@Input()` i `@Output()`,
- ukrywanie polega na zmianie wartości zmiennej typu `boolean` albo przechowywaniu `null`/wybranego obiektu.
